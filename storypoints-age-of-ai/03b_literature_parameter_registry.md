# Route B Literature-Informed Parameter Registry

**Version:** 0.1 evidence anchors  
**Status:** Source-grounded candidate records, not a calibrated parameter set

These records prevent empirical findings from being silently converted into simulation truth. A compatible observed estimate is `E1`; a reproducible transformation would be `E2`; heterogeneous evidence may bound an `L` scenario; an `I` value is deliberately illustrative. None of the sources below estimates a universal distribution for role-stage demand, gate failure, rework, or organizational capacity.

## Transformation rule

A registry row becomes an executable numerical parameter only when a separate extraction record states: population/task compatibility, original estimand and uncertainty, target model unit, formula, distribution family rationale, bounds, correlation assumptions, extractor, verifier, source checksum/version, and sensitivity alternative. Otherwise it remains an evidence anchor and the configuration must label its number `I` or `L`, not `E1`.

## Current parameter gaps

No defensible direct empirical values have yet been extracted for role-specific active service-time distributions, cross-role arrival correlations, context-switch setup penalties, evidence-gate evaluation time, conditional-pass frequency, rework routing, release/UAT demand, risk-scaled gate effectiveness, or measurement overhead. Published elapsed pull-request duration must remain separate from active human touch time. These inputs remain illustrative in Route B and prospective Route A targets until full-text, locator-level extraction is verified.

The executable coverage audit is in `02b_active_parameter_gap_audit.md`; its machine-readable registry is `simulation/configs/parameter_registry.json`. The checker currently maps 102 active configuration paths to nine unique provenance records. All active calibration and comparator-input records remain class `I`, so development simulation is permitted while production calibration fails closed.
