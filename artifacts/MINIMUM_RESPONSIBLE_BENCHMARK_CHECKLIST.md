# Minimum Responsible Benchmark Report Checklist

**Version**: 1.0  
**Date**: 2026-08-20  
**Purpose**: Ensure transparent, complete AI benchmark reporting aligned with NIST AI 800-2

## Pre-Registration

- [ ] Research question stated before data access
- [ ] Hypotheses frozen before evaluation
- [ ] Success criteria defined prospectively
- [ ] Comparator set registered
- [ ] Held-out data protocol specified

## Measurement Target

- [ ] Precise construct definition
- [ ] Operational metric specification
- [ ] Boundary conditions documented
- [ ] Known limitations disclosed
- [ ] Construct validity evidence

## Multi-Criteria Evaluation

- [ ] Safety metrics reported
- [ ] Cost metrics reported
- [ ] Completion/reliability metrics reported
- [ ] Authorization/compliance metrics reported
- [ ] Operational burden metrics reported
- [ ] Conjunctive gate results disclosed

## Single-Metric Reporting

- [ ] Primary metric justified
- [ ] Rank-reversal analysis performed
- [ ] Multi-criteria comparison included
- [ ] Trade-off analysis documented
- [ ] Optimization target disclosed

## Threshold Sensitivity

- [ ] Threshold selection rationale
- [ ] Sensitivity analysis (±10%, ±20%)
- [ ] Decision stability reported
- [ ] Brittle decisions flagged
- [ ] Robustness assessment

## Negative Results

- [ ] Failed criteria disclosed
- [ ] Unfavorable comparisons reported
- [ ] Dominated methods identified
- [ ] Null findings preserved
- [ ] Limitations acknowledged

## Comparator Fairness

- [ ] Information parity verified
- [ ] Strongest simple baseline included
- [ ] Comparator implementation validated
- [ ] No retrospective advantages
- [ ] Tie-breaking rules disclosed

## Reproducibility

- [ ] Data provenance documented
- [ ] Code/protocol versioned
- [ ] Random seeds fixed
- [ ] Integrity hashes provided
- [ ] Replication instructions complete

## Deployment Readiness

- [ ] Deployment context specified
- [ ] Operational constraints documented
- [ ] Human oversight requirements
- [ ] Failure mode analysis
- [ ] Scalability assessment

## Reporting Transparency

- [ ] All registered hypotheses reported
- [ ] Passed and failed criteria disclosed
- [ ] Descriptive vs. inferential claims distinguished
- [ ] Confidence intervals/uncertainty reported
- [ ] Claim-to-evidence ledger provided

---

## Usage

**For Authors**: Complete before submission. Attach as supplementary material.

**For Reviewers**: Verify completeness. Flag missing items.

**For Practitioners**: Assess deployment readiness beyond headline metrics.

---

## Alignment

- **NIST AI 800-2**: Measurement target, evaluation correctness, transparent reporting
- **RAER, OVAR, VDCM**: Prospective gates, negative results, multi-criteria evaluation
